# 包装规范（固定规则）

下表描述通用包装。卖家案例口播沿用 `seller_reference` 的原稿参数：常规单句白字、黑色阴影、字号 12、淡黄 `#FFF589` 强调，普通镜头硬切。递进或对照短语可在 `beat.caption.cues` 中逐条填写相对本拍的 `at` 秒数和 `text`，堆叠用 `mode:"stack"`。观点转折需要短暂的圆形构图时，按该句在拍内的起点指定 `circle_mask`。三种案例的依据和适用剪点可查 `get_video_workflow(profile="reference",detail="profile")`。
参数由 `compile_episode` 落实；这里列出的是会被写进剪映草稿和预览的实际数值。

配套的可运行样例：`examples/episodes/packaged-talk-template.json`（分镜骨架）、
`examples/episodes/meigong-outsource-vs-inhouse.json`（成片级示例）。

---

## 1. 字幕

### 1.1 样式

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 字号 | **11.5**（`caption_size`） | 竖屏默认值，组内各行保持相同字号 |
| 字体 | 跟随 `style_preset` | `editorial` → HarmonyOS_Sans_SC_Bold；不要另指定字体 |
| 颜色 | 近白 `#FAFAE8` | 由风格给出，不要写纯白以外的自定义色 |
| 字重 | 粗体 | 始终开启 |
| 描边 | 深色，宽 10，不透明度 0.72 | 由风格给出，保证浅色画面上也读得清 |
| 最大行宽 | 0.9 | 自动换行，不要手写 `\n` 硬折行 |
| 对齐 | 居中 | 单行居中；`blocks` 模式按栏分块 |
| 重点色 | 暖黄 `#FFDB4D` | 见 1.4 |

字号低于 11 在竖屏手机上看不清；不要为了塞进一句话而缩字号，改用 `blocks` 或 `words` 拆句。

### 1.2 位置

字幕**不固定**在底部，按画面内容落位：

| 值 | 纵向位置 `transform_y` | 画面位置 |
| --- | --- | --- |
| `top` | +0.74 | 上方，人物在下方时 |
| `upper` | +0.36 | 上中，人物在下半身时 |
| `lower` | −0.40 | 下中，人物在上半身时 |
| `bottom` | −0.74 | 底部，默认 |

- 默认 `caption_zone: "auto"`：抽该选段的 3 帧，按肤色和细节打分，自动选不压脸的带；同一素材段保持同一落位。
- 分屏（`layout`）时，字幕固定在**主讲人那一栏**：`main:"bottom"` → `bottom`，`main:"top"` → `upper`，绝不会跑到卡片栏。
- 全屏动效卡上的字幕固定 `bottom`。
- 需要精确控制时按拍写 `caption: {"zone": "lower"}` 或 `caption: {"y": -0.55}`（−0.95–0.95，正数向上）。

### 1.3 呈现方式与入场动画

`caption_mode` 决定一句话怎么出现，默认 `single`。每条字幕自带入场动画，不需要额外配置。

| `caption_mode` | 效果 | 剪映动画 | OpenFilm | 时长 |
| --- | --- | --- | --- | --- |
| `single` | 整句一次出现并弹入 | 弹入 | `rise` | 240ms |
| `stack` | 预先排定上下行，依次整句出现 | 渐显 | `fade` | 160ms |
| `blocks` | 列举项按字宽相邻摆放，过宽转为上下行 | 渐显 | `fade` | 160ms |
| `words` | 按停顿短语逐段累加 | 渐显 | `fade` | 150ms |

- 组内所有行在末项结束时一起退场；新项入场期间，已出现的行保持原位和字号。
- 普通陈述用 `single`。长句有两个独立分句，或列举、递进有明确语义断点时，才使用 `stack`、`blocks`。`words` 是单句入场。
- 回听断点，数字与单位、否定词与被修饰的词应完整。整片普通口播可全部采用单句。

```json
{"kind": "talk", "source": "...", "start": 12.0, "end": 21.6,
 "caption": {"mode": "blocks"}}
```

### 1.4 重点标黄

字幕里出现的下列词语逐字标暖黄 `#FFDB4D`：分屏卡上的要点标题、`caption_keywords`、该拍的 `highlights`。
不要整句标色，一条字幕最多两处。

```json
{"caption_keywords": ["外包", "自养", "需求表", "试稿"]}
```

### 1.5 断行与标点

按分句断行，不在词中间切断，标点不会出现在行首。默认 `caption_punctuation: "spaced"`：
逗号、句号等停顿标点改成空格或去掉；问号、叹号、引号、书名号保留。`keep` 保留全部，`strip` 全部去掉。
`caption_max_chars` 默认 14（竖屏）。不要手写换行符或手动插入空格对齐。

## 2. 转场

`transitions: "auto"`（默认）：

- 画面类型变化处加短转场：实拍 ↔ 动效卡、`media` 切换、小节第一拍。
- 同机位口播之间**硬切**，不加转场——连续说话时转场会打断语流。

转场由 `style_preset` 决定，不要手写名称：

| `style_preset` | 剪映转场 | 半程时长 | 预览 |
| --- | --- | --- | --- |
| `editorial`（默认） | 闪黑 | 0.17s | `dip` |
| `documentary` | 叠化 | 0.23s | `dip` |
| `broadcast` | 向右擦除 | 0.13s | `wipe_right` |
| `clean` | 向左擦除 | 0.12s | `wipe_left` |

`"all"` 每个切点都过渡（快剪、蒙太奇用），`"none"` 全硬切。单拍要关掉写 `"transition": false`。
转场总长控制在 0.3 秒内，超过会和口播抢节奏。

## 3. 分镜与动效卡

### 3.1 三种 beat

| `kind` | 用途 | 必备字段 |
| --- | --- | --- |
| `talk` | 口播原声 | `source`、`start`、`end`（可省 `text`，自动读转写） |
| `media` | B-roll、录屏、生成视频 | `source` + `start`/`end` 或 `seconds`（静音） |
| `graphic` | 全屏动效卡 | `recipe`、`data`、`seconds`（可省，用配方默认值） |

一条片子的骨架：`hook` → 3–4 个小节（口播 + 分屏）→ 总结卡（带原声）→ `end`。
同一意思在一个构图内说完。卖家口播通常每镜停留 5–8 秒，复杂操作、问答清单可以更久。需要补充证据时再切全屏或人物分屏。

### 3.2 分屏

```json
{"kind": "talk", "source": "D:/素材/口播.mp4", "start": 12.0, "end": 21.6,
 "layout": {"kind": "stacked", "main": "bottom", "split": 0.5,
            "with": {"graphic": {"recipe": "list", "data": {"items": [{"title": "快", "at": 3.0}]}}}}}
```

- `kind`：`stacked`（上下分屏，默认）或 `interview_box`（下方描边框）。
- `main`：主讲人在 `bottom`（默认）还是 `top`。两栏轮换能避免整期都是同一构图。
- `split`：上栏占比 0.30–0.65，默认约 0.5。
- `with.graphic` 按栏位实际尺寸渲染，卡不会被裁成横条。`with.media` 放实拍或生成视频，可设 `start`、`focus`、`fit`（`cover` 裁切铺满 / `contain` 完整显示）。
- `items[].at` 是相对本拍开始的秒数，必须与口播提到的时刻对齐。估算：
  `at = 本拍时长 × 关键词之前字数 ÷ 全句字数 − 0.15`。

### 3.3 动效卡配方

`list_motion_recipes` 可查实时字段。常用：

| 配方 | 角色 | 字段 | 默认时长 | 用在哪 |
| --- | --- | --- | --- | --- |
| `hook` | 开场 | `eyebrow` `title` `subtitle` | 3.0 | 片头第一拍，一句提问 |
| `chapter` | 小节 | `index` `title` | 2.2 | 只放编号和标题，不写内容 |
| `list` | 复述 | `eyebrow` `title` `items` | 4.2 | 三件事、理由、清单 |
| `steps` | 复述 | `title` `items` | 4.4 | 先后关系、流程 |
| `checklist` | 复述 | `title` `items` | 4.0 | 判断条件（“什么时候该……”） |
| `compare` | 复述 | `title` `left` `right` | 4.6 | 两栏对照 |
| `number` | 强调 | `value` `unit` `label` `note` | 3.0 | 规模、时长、量级 |
| `quote` | 强调 | `text` `source` | 3.2 | 立场、金句 |
| `headline` | 强调 | `eyebrow` `title` | 6.0 | 分屏里标这段在讲什么 |
| `end` | 片尾 | `brand` `slogan` `cta` | 3.4 | 署名与行动号召 |

结构规则（编译时检查，违反会报错）：

- 需要记录小节位置时，在口播 beat 上写 `chapter`。
- `list`/`steps`/`checklist`/`compare` 这类复述卡在小节里只能放进口播分屏，随讲随出。
- 全屏复述卡只允许出现在总结段，总结段第一拍标 `"role": "summary"`。
- 全屏 `graphic` 只用于：开场 `hook`、短停强调（`quote`/`number`/`headline`）、片尾 `end`、总结段。

### 3.4 小节剪点

```json
{"kind": "talk", "source": "...", "start": 60.0, "end": 83.0,
 "chapter": "03 找外包做到三件事"}
```

- 该标记用于小节切换和转场，口播与分屏画面都省去小节角标。
- 要点卡可保留表达内容所需的标题与序号。

## 4. 总结段

总结用卡片承载原声，人不用出镜：

```json
{"kind": "graphic", "recipe": "compare", "role": "summary",
 "voice": {"source": "D:/素材/口播.mp4", "start": 142.0, "end": 154.0,
           "text": "内部定标准，外包做产能。"},
 "data": {"title": "最好的结构",
          "left": {"title": "内部 · 定标准", "items": ["品牌调性", "合规红线", "数据标准"]},
          "right": {"title": "外包 · 做产能", "items": ["批量出图", "大促突击", "多店并行"]}}}
```

- 省略 `seconds` 时卡片时长 = `voice` 时长。
- 工具从原素材裁出该段人声放旁白轨，字幕按这段话走，`items[].at` 照常对齐。
- 总结卡最多 2 张，每张 3–4 条；不要在总结里再放一段口播实拍。

## 5. 成片自检清单

发布前逐条核对，任何一条不符就回去改分镜：

1. 每条字幕字号 ≥ 11.5，没有被缩到 10 以下塞整句。
2. 字幕没有压住人脸或演示区域；分屏时字幕在主讲人一栏。
3. 一条字幕最多两处黄字，且是名词或关键短语。
4. 每组多字幕能指出原话中的逗号、递进关系或列举停顿；全组落位后清晰可读。
5. 小节角标已省略。全屏复述卡在总结段。
6. 每个转场都在画面类型变化处，同机位口播之间是硬切。
7. 观众能看清完整动作、读完最后一项，插镜前后留足时间。卖家风格默认检查可见分镜的 4 秒下限。
8. 分屏 `items[].at` 与口播实际提到的时刻对齐（听一遍，误差 < 0.4 秒）。
9. 总结段有卡片 + 原声，`role: "summary"` 已标注。
10. `warnings` 为空或已逐条处理（副画面大幅裁切、字号偏小、繁体字体等）。

清单和结构校验只能说明字段齐全。`keyframes` 出现只代表排了运动，`items[].at` 出现只代表排了时点——都没看过的画面写「待目检」，不要写成已通过。

## 6. 审片记录

按下面的格式逐条记，时间用实际返回的 `frames[].time_ms` 或成片时码：

```
成片区间｜预期｜实见｜结论
5.20–5.80 秒｜点击后出现确认标记｜画面已切回人脸，标记未出现｜延长录屏，再查同一处
```

各类要点各查一处就够，不必全片铺开：

| 查什么 | 时间窗 | 看什么 |
| --- | --- | --- |
| `stack` 堆叠 | 第二句入点前一帧到淡入完成 | 第一行位置和字号恒定，两行都读得全 |
| `blocks` 分块 | 最挤的一帧 | 左右块仍有间隔，没有叠字 |
| `words` 累加 | 任意两次入场之间 | 前缀依次累加，无重影 |
| 单句入场 | 首字、运动中、稳定帧 | 没有提前消失或跳位 |
| 分屏要点 | 每项 `at` 前后各 0.4 秒 | 讲到的词和出现的项对得上 |
| 转场 | 切点前后各 0.3 秒 | 没有突断的动作或音节 |

只有一条 cue 时只能检查单句入场；只有工程没有 MP4 时先记工程预览，导出后补成片实见。
